## ERDPlus für Datenbank-Modellierung

Neue Version zum ersten Mal.

### Workflow

1. Entity-Relationship-Modell (Chen)
    - Entität: am Geschäftsprozess beteiligte Person oder Ding
    - beteiligte Entitätstypen identifizieren
    - Beziehung (Linie und Raute, Verb in Raute)
    - Kardinalität festlegen: 1:1 | 1:n | n:m
      - Strich für 1, Krähenfuß für n oder m, * für n oder m
    - Attribute ergänzen: Ellipsen → Spalten in der Tabelle
      - Primärschlüssel (Primary Key) wird unterstrichen und muss eindeutig sein
      - weitere Attribute sind beschreibende Attribute
      - verschiedenartige Daten auf mehrere Attribute verteilen
2. Konvertieren in Relationenmodell
    - Darstellung angelehnt an UML-Klassendiagramm
      - Rechteck = Klasse = Entitätstyp = Tabelle
    - Foreign Keys (FK) werden sichtbar am "viele"-Ende von 1:n-Beziehungen
    - auf der "1"-Seite der Beziehung sitzt der Primary Key (PK)
    - n:m-Beziehungen werden ersetzt durch eine Zwischentabelle und zwei 1:n-Beziehungen
    - typischerweise bilden in der Zwischentabelle die FKs zusammen den Primary Key
    - für jedes Attribut Datentypen festlegen
3. SQL-Code zum Erstellen von Tabellen generieren
    - `CREATE TABLE`-Anweisungen

## Aufgabe: Datei vs. Datenbank

### Unterschied Datei vs. Datenbank

- **Datei:** unstrukturiert, kein Schutz vor Mehrfachzugriff, keine Konsistenzprüfung, Beziehungen zwischen Daten schwer abbildbar
- **Datenbank (DBMS):** strukturierte Tabellen, erzwingt Regeln (z. B. Pflichtfelder, Eindeutigkeit), regelt Mehrbenutzerzugriff, kann Beziehungen abbilden

### Argumente für den Einsatz einer Datenbank

- Redundanzvermeidung (keine doppelten/widersprüchlichen Daten)
- Datenintegrität wird vom System erzwungen
- Mehrbenutzerbetrieb (mehrere Nutzer arbeiten gleichzeitig sicher)
- Zugriffskontrolle (Rechte auf Tabellen-/Spaltenebene)
- Audit-Fähigkeit (nachvollziehbar, wer was getan hat)
- Verlässliche, feste Struktur
- Performance auch bei großen Datenmengen
- Skalierbarkeit
- Flexible Abfragen (SQL statt manuellem Suchen)

### Erwartete Funktionsmerkmale einer Datenbank

- SQL-Abfragesprache (SELECT, JOIN, ...)
- Transaktionssicherheit (ACID)
- Backup/Recovery
- Zugriffsrechte
- Indizierung (schnelle Suche)
- Primär-/Fremdschlüssel für Beziehungen (1:1, 1:n, n:m)

### Datenbanktypen

#### Relationale Datenbanken

- Relation = Tabelle
- sehr strenge, feste Struktur (Schema)

#### NoSQL ("not only SQL")

- flexiblere Struktur, oft schemalos
- Typische Kategorien:
  - Dokumentdatenbanken (z.B. MongoDB, Speicherung als JSON-/XML-Dokumente)
  - Key-Value-Stores (z.B. Redis)
  - Spaltenorientierte Datenbanken (z. B. Cassandra)
  - Graphdatenbanken (z.B. Neo4j)
