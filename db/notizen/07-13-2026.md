## Notizen

- Einfüge-Anomalie
  - Beim Einfügen einer neuen Zeile kann nicht der vollständige PRIMARY KEY angegeben werden.
- Änderungs-Anomalie
  - Beim Aktualisieren von Daten wird eine Instanz einer Entität übersehen, so dass Widersprüche in den Daten entstehen.
- Lösch-Anomalie
  - Beim gezielten Löschen einer Entität wird unabsichtlich eine weitere Entität eines anderen Typs gelöscht.

## Abfolge von Schritten bei Bearbeitung von Modellierungsaufgabe

Jedes Modell bekomt in ERDPlus einen eigenen ordner und im persönlichen Repository ein neues Jupyter-Book im Ordner db/modelle. Ein neues Jupyter-Book erzeugt einen Unterodner unter db/modelle. In jedem Jupyter-Book-Ordner erstellen wir die Unterordner png und erdplus.

Die ersten vier Schritte haben ein Label mit dem Namen des Autors im Diagramm. Ergebnisse sind jeweils eine ERDPlus und eine PNG-Datei

1. Entitätstypen, Beziehungen, Kardinalitäten
2. Primary Keys (UNIQUE-Attribute, die jede einzelne Entität eindeutig identifizieren)
3. Beschreibende Attribute, Daten angemessen auf verschiedene Attribute verteilt. Möglicherweise sind optionale Attribute dabei.
4. Umwandlung in Relationen Modell
    - Neues Label mit dem Namen des Autors
    - Zwischentabellen anschaulich benennen
    - Attributnamen sollen keine Leerstellen haben
    - Datentypen festlegen
5. In ERDPlus SQL-Befehle zu dem Relationen Modell erzeugen
    - Code in eine Markdown Datei im Jupyter-Book übernehmen
    - Darf nicht ausgeführt werden, weil die Angabe fehlt, in welche Datenbank die Tabellen kommen
6. SQL Code anpassen und erweitern in einem Jupyter-Notebook
    - USE master; später: USE DatenbankName;
    - DROP DATABASE IF EXISTS DatenbankName;
    - GO Anweisungen nach einschneidenden DDL-Befehlen
    - CREATE DATABASE DatenbankName
    - CONSTRAINT Syntax für PKs und FKs
    - pk_tabellenname
    - fk_tabellenname_reftabelle
7. Datenerfassung mit INSERT und Transaktionen
8. Abfragen und Views (Sichten)
